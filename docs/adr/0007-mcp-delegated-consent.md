# ADR-0007. MCP: CIMD с белым списком, ресурсы из конфигурации, делегированное согласие

Статус: предложено, 15.10.2026. Сверено со спецификацией MCP 2026-07-28 и документацией Claude по коннекторам.

## Контекст

Claude подключается к MCP-серверам приложений как публичный OAuth-клиент. Он выбирает CIMD, только если
метаданные сервера авторизации содержат `client_id_metadata_document_supported: true` и `none` в
`token_endpoint_auth_methods_supported`; иначе — DCR, которая в MCP 2026-07-28 устарела и которую мы не делаем.
Claude использует redirect `https://claude.ai/api/mcp/auth_callback`, Claude Code — loopback на случайном порту
(`http://localhost/callback`, `http://127.0.0.1/callback` в его CIMD). Права доступа (какой проект, чтение или
запись) знает только приложение-ресурс.

## Решение

- CIMD: скачиваем документ только с хостов из белого списка (сначала `claude.ai`), без редиректов, ≤ 16 КБ,
  5 с, адрес назначения не частный, кэш по `Cache-Control` ≤ 24 ч; `client_id` в документе совпадает с URL;
  `token_endpoint_auth_method` = `none`.
- `redirect_uri` проверяется дважды: по документу клиента и по глобальному белому списку; у loopback не
  сравнивается порт.
- Ресурсы (MCP-серверы) заведены в конфигурации с приложением-владельцем; `resource` обязателен; `aud` токена —
  ресурс.
- Делегированное согласие по образцу Ory Hydra: `consent_challenge` → страница приложения → серверный API
  (`GET /api/consent/{challenge}`, `POST …/accept|reject`, Basic-аутентификация владельца ресурса) → одноразовый
  `consent_verifier`, привязанный к SSO-сессии → код.
- Страница согласия приложения обязана показать название клиента, хост `redirect_uri` и предупреждение для
  loopback (MUST спецификации MCP). family-id отдаёт эти данные в API; чек-лист и шаблон — в `docs/integrate.md`.
- `remember`: приложение может разрешить не спрашивать повторно, пока грант жив и новые `scope` не шире прежних.

## Последствия

- Каждое приложение с MCP пишет свою страницу согласия (бухгалтерия — выбор проекта и прав) и интроспекцию.
- Новые ассистенты добавляются расширением белых списков в конфигурации, без кода.
- Ответственность за показ хоста клиента делится: family-id отдаёт данные, приложение показывает. Проверяется
  при подключении приложения (чек-лист).

## Отвергнутые варианты

- Своя страница согласия family-id для MCP — не знает проектов и прав приложения; два экрана подряд хуже для
  пользователя.
- Открытая DCR — устарела в MCP, открывает регистрацию произвольных клиентов.
- Anthropic-held client credentials (`oauth_anthropic_creds`) — требует договорённости с Anthropic; CIMD работает
  сразу и для Claude Code.

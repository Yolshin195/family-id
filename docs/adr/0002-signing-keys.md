# ADR-0002. Ключи подписи: EdDSA по умолчанию + RS256

Статус: предложено, 15.10.2026. Решение владельца — «EdDSA по умолчанию + RS256».

## Контекст

Задача требует подпись EdDSA (Ed25519). OIDC Discovery 1.0 требует, чтобы `id_token_signing_alg_values_supported`
содержал RS256; OpenID Conformance Suite проверяет провайдер по спецификации. Часть клиентских библиотек EdDSA не
поддерживает. Бухгалтерия (`openidconnect` 4.0.1) берёт допустимые алгоритмы из метаданных провайдера.

## Решение

- Два активных ключа: Ed25519 (`EdDSA`) и RSA 2048 (`RS256`), оба в JWKS. `kid` — отпечаток JWK по RFC 7638.
- Алгоритм выбирается для каждого клиента: `id_token_signed_response_alg` в конфигурации, по умолчанию `EdDSA`.
  Клиенты Conformance Suite и клиенты со старыми библиотеками — `RS256`. Logout token и SET подписываются тем же
  алгоритмом, что и ID-токены клиента.
- Закрытые ключи хранятся в `fid_signing_keys`, зашифрованные AES-256-GCM мастер-ключом `FID_KEY_ENCRYPTION_KEY`
  (из окружения или `*_FILE`; associated data — `kid`). Без мастер-ключа продакшен не стартует.
- Жизненный цикл: «следующий» ключ публикуется в JWKS за 7 дней до начала подписи → подписывает 90 дней →
  остаётся в JWKS ещё 30 дней (дольше любого токена, подписанного им) → удаляется. Проверяет и выполняет фоновая
  задача; `family-id keys rotate [--now]` — вручную (`--now` — для тестов и при компрометации: старый ключ сразу
  перестаёт подписывать, но остаётся в JWKS).
- JWKS отдаётся с `Cache-Control: max-age=600`; клиенты, не нашедшие `kid`, перечитывают JWKS (бухгалтерия уже так
  делает).

## Последствия

- Проходят тесты Suite на подпись; клиентам доступен быстрый и компактный EdDSA.
- Копия базы без мастер-ключа не даёт подделывать токены. Мастер-ключ нужно хранить отдельно и не терять: при
  потере — новые ключи (`keys rotate --now`) и повторный вход у клиентов.
- Ротация мастер-ключа — команда `family-id keys rewrap` (v1.1).

## Отвергнутые варианты

- Только EdDSA — нарушает OIDC Discovery и, вероятно, роняет часть Conformance Suite.
- Только RS256 — противоречит задаче, длиннее токены.
- Ключи в файлах на диске — сложнее ротация и резервные копии; шифрование в БД даёт то же с одной копией базы.

# ADR-0008. Тестовый вход и исключение PKCE только в сборке conformance

Статус: предложено, 15.10.2026.

## Контекст

Критерий готовности v1 — проход профилей OpenID Conformance Suite в CI. Suite проходит вход в браузере-роботе
(HtmlUnit), который не поддерживает WebAuthn, а единственный способ входа v1 — passkey. Кроме того, план Basic OP,
по-видимому, отправляет запросы без PKCE, а у нас PKCE обязателен (проверить на этапе 1).

## Решение

- Cargo-флаг `conformance` в `app` добавляет тестовый способ входа: форма «логин / пароль» для заранее заданных в
  конфигурации тестовых аккаунтов, `amr = ["pwd"]`.
- Только при этом флаге клиент может иметь `pkce = "optional"`; для таких клиентов `nonce` обязателен
  (RFC 9700 §2.1.1 допускает `nonce` вместо PKCE для конфиденциальных OIDC-клиентов).
- Выпускаемый образ собирается без флага; бинарь с флагом отказывается стартовать при `FID_ENV=prod`; в CI есть
  проверка, что выпускаемый образ не содержит строк тестового входа.
- Conformance-сборка запускается только в CI и локально в `compose.conformance.yaml`.

## Последствия

- Код тестового входа существует в репозитории, но не попадает в продакшен ни флагом, ни конфигурацией.
- Если окажется, что Suite отправляет PKCE, исключение для PKCE удаляется.

## Отвергнутые варианты

- Виртуальный аутентификатор в Suite — HtmlUnit его не поддерживает.
- Тестовый вход, включаемый переменной окружения, — один неверный параметр в продакшене открыл бы вход без
  passkey.

# ADR-0006. SSO-сессии, единый выход, back-channel logout и SET

Статус: предложено, 15.10.2026.

## Контекст

Нужно: вошёл в одном приложении — в остальных вход без нажатий; вышел в одном — вышел во всех в этом браузере;
«выйти везде» — все устройства и все приложения; удаление аккаунта сообщается приложениям. Сторонние cookie в
браузерах заблокированы, поэтому iframe-механизмы (Session Management, front-channel logout) ненадёжны.

## Решение

- SSO-сессия — cookie `__Host-fid_session` (256 бит, в БД хеш), публичный `sid`. Простой 30 дней, максимум
  90 дней, свежая аутентификация ≤ 10 мин для опасных действий. Сроки настраиваются.
- SSO в приложениях — верхнеуровневый редирект `/authorize?prompt=none` (cookie `SameSite=Lax` при нём
  отправляется).
- Для каждой сессии хранятся клиенты-участники (`fid_session_clients`).
- Закрытие сессии по любой причине → back-channel logout каждому участнику через outbox в БД (повторы в течение
  часа, новый `jti` на каждую попытку).
- RP-Initiated Logout без экрана подтверждения, если `post_logout_redirect_uri` зарегистрирован у клиента;
  `id_token_hint` необязателен.
- Удаление аккаунта → Security Event Token RISC `account-purged` (RFC 8417), push по RFC 8935 на `events_uri`
  клиента. Тот же канал — для блокировки аккаунта.

## Последствия

- Приложения должны реализовать приём logout token и SET (описано в `docs/integrate.md`, для бухгалтерии — после
  её доработки).
- Выход в одном приложении закрывает и остальные в этом браузере — это ожидаемое поведение единого выхода; если
  приложение хочет выйти только у себя, оно не вызывает `end_session_endpoint`.
- Выход без подтверждения может инициировать чужой сайт ссылкой — только с зарегистрированным адресом возврата;
  ущерб — повторный вход в одно касание.

## Отвергнутые варианты

- Front-channel logout и `check_session_iframe` — не работают без сторонних cookie.
- Собственный формат события удаления — стандартный SET RISC переиспользуем и понятен библиотекам.

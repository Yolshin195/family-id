# ADR-0001. Эталон rust-hex-api и его расширения

Статус: предложено, 15.10.2026.

## Контекст

Задача требует эталон скилла `rust-hex-api` (v2): Cargo workspace, фича = крейт, зависимость только от kernel,
порты и адаптеры, связки в `crates/app/src/wiring`. Эталон рассчитан на REST API с JWT и CRUD-фичами
(`directory`, `journal`, `blank`). У family-id другой профиль: серверные страницы, cookie-сессии, протоколы OIDC
и OAuth, фоновая доставка событий. Бухгалтерия уже расширила эталон похожим образом (kernel `web`, `i18n`,
`crypto`, `config`, `throttle`; страницы в `adapters/web.rs` фич).

## Решение

1. Проект создаётся `arch.py init` (эталон v2), все фичи — тип `blank`, логика пишется вручную внутри крейтов.
2. Kernel расширяется, как в бухгалтерии: `config` (TOML + env + `*_FILE`), `crypto` (случайные токены, SHA-256,
   HMAC, AES-GCM), `i18n` (`Lang`, `Tr`), `web` (PageCtx, каркас, рендер, ошибки, заголовки, CSP, статика),
   `throttle`, `request` (IP за прокси, проверка Host), `audit` (порт журнала безопасности). Файл `auth.rs` (once)
   заменяется: текущий пользователь — из cookie SSO-сессии, CSRF, свежая аутентификация; JWT-middleware эталона не
   используется.
3. **Отклонение: все страницы — в одной фиче `portal`.** Вход, регистрация, согласие и кабинет сочетают сразу
   несколько фич (passkey + сессии + поток OIDC + брендинг клиента). Если раскладывать страницы по фичам, шаблонам
   пришлось бы знать чужие фичи. `portal` зависит только от kernel и объявляет порты к сценариям; адаптеры — в
   `wiring/wire_portal.rs`. Остальные фичи не содержат HTML, только JSON (`passkeys` — для `webauthn.js`) и
   протокольные эндпоинты (`oidc`).
4. Внешних ключей между таблицами разных фич нет (правило эталона). Удаление аккаунта каскадно проходит через
   порт `AccountErasure`, который в wiring вызывает удаление в `passkeys`, `sessions`, `oidc`, `upstream`.
5. Swagger (utoipa) — только для серверного API `/api/*` (делегированное согласие), при `SWAGGER=1` и не в prod.
   Протокольные эндпоинты описаны стандартами и в OpenAPI не дублируются.
6. Фоновые задачи (outbox, чистка, ротация ключей) запускаются в `app` и вызывают публичные методы сервисов фич.
7. CLI (`serve`, `migrate`, `recovery-link`, `keys rotate`, `users …`) — подкоманды того же бинаря в `app`.

## Последствия

- `cargo test -p <фича>` работает без БД и без других фич, как требует эталон.
- Правка страниц пересобирает только `portal` и `app`.
- `portal` — самая крупная фича; если она разрастётся, её можно разделить на `portal_login` и `portal_account`
  без изменения остальных.
- Расширения kernel — кандидаты в следующую версию эталона (общие с бухгалтерией: `web`, `i18n`, `crypto`).

## Отвергнутые варианты

- Страницы внутри каждой фичи (как в бухгалтерии) — вход и кабинет собирают данные нескольких фич; пришлось бы
  связывать фичи напрямую или дублировать каркас.
- Одна большая фича `idp` — теряется независимое тестирование и выключение (`upstream`, `mcp_clients`).
